# Known Issues

## Earthsiege 2 (original retail game)

_Bugs listed in this section were tested on Windows 11. It's possible that some bugs would not occur on original 1990s hardware. Bugs in this section are reproduced as-is in HERCULAN Engine unless otherwise noted.

Some of the bugs in this section were filed by Claude and are un-verified. Claude frequently concludes that a memory address/feature is unreachable and unused in retail, when in fact the mechanism for accessing this address/feature simply has not been found yet; any claim to this effect should be viewed with skepticism. Likewise, Claude sometimes confuses save files with the full set of retail missions, so any claim that a feature is never used in any retail mission should be viewed with skepticism._

_Note to Claude: Detailed technical descriptions belong in their respective docs, not here. Give a short plain-English summary._

### Cosmetic
- Samson cockpit: several HUD elements are slightly misaligned (shield balance text is not centered horizontally with meter; firing chain, LINK, and TRACK buttons are slightly too high and too far outward)
- Herc stats shown in the VSHELL "Build" screen may be incorrect (the Outlaw is listed as having a top speed of 80 kph, but the manual and in-game readout show 100 kph; the Raptor II is advertised with 4 hardpoints where the actual Herc has 5. See [`docs/formats/herc-catalogs.md`](docs/formats/herc-catalogs.md#gamherc_infdat--the-chassis-stat-table).
- The cockpit computer says `ENEMY TARGET DESTROYED` when you destroy a **friendly** machine you had selected. The announcement only checks that the player fired the killing shot and that the victim was the player's own selected target; it never checks whose side the victim was on. Reproduced as-is in HERCULAN Engine. See [`docs/formats/cockpit-messages.md`](docs/formats/cockpit-messages.md#posters).
- The cockpit computer never says `DAMAGE LEVEL CRITICAL`due to a typo in the code. **Fixed** in HERCULAN as an optional Tweak. See [`docs/formats/cockpit-messages.md`](docs/formats/cockpit-messages.md#posters).
- The compass's power-up wind-up only works in one direction, with rotation finishing instantly in the other direction. Reproduced as-is. Note that by design the windup animation is not played when piloting the Razor. See [`docs/formats/cockpit-gunsight-hud.md`](docs/formats/cockpit-gunsight-hud.md#power-up-wind-up).
- The HUD speed readout does not reflect speed accurately. Hercs have two strides, "walking" and "running". In the walking stride, the Herc moves much more slowly than the speed gauge indicates. Reproduced as-is. See [`docs/simulation/mech-locomotion.md`](docs/simulation/mech-locomotion.md#walkrun-gait-discontinuity).
- An ELF or ELF2 shot paints a stray orange-white dash at the muzzle, roughly four pixels wide, where the jagged tracer branch falls through into the straight-beam draw. See [`docs/simulation/beam-visuals.md`](docs/simulation/beam-visuals.md#the-muzzle-stub-is-a-retail-fall-through).
- In the low-memory mode (`-l`, or under 12 MB physical), catalog id `0x22`'s explosion sound fails to open and plays silently — its sample exists only in the `hmi\` bank, not the `hmx\` bank low-memory mode uses. See [`docs/formats/audio.md`](docs/formats/audio.md#sample-banks).
- Turning MUSIC off in the preferences does not keep it off. Starting a mission forces the music flag back on after it has already decided not to play a track, so the CD stays quiet until anything resumes the sound — alt-tabbing away and back is enough — and then plays. **Not reproduced** in HERCULAN Engine. See [`docs/formats/audio.md`](docs/formats/audio.md#the-mission-session-overrides-the-music-preference).
- Setting PILOT MESSAGE to TEXT ONLY also silences the cockpit computer's voice, whatever COMPUTER MESSAGE says: the PILOT MESSAGE row switches off all recorded speech, not just the squad's. With COMPUTER MESSAGE on VOICE ONLY the computer then says nothing at all, in text or voice. Reproduced as-is. See [`docs/formats/cockpit-messages.md`](docs/formats/cockpit-messages.md#the-port).
- `Sound_Place`'s pan calculation snaps a sound placed exactly abeam the listener to the wrong side: bearing zero truncates to the hard-*left* value where every neighbouring bearing on both sides yields hard-*right*. Not reproduced in HERCULAN Engine. See [`docs/formats/audio.md`](docs/formats/audio.md#playing-a-sound).
- The [F11] objectives panel prints its objective text five pixels right of centre. Reproduced as-is. See [`docs/simulation/mission-objectives.md`](docs/simulation/mission-objectives.md#geometry).
- The Range readout of the MFD TARGET tab (F5) prints raw world units — 1 unit = 6 mm. Every other distance readout in the cockpit converts to metres first (`Hud_WorldUnitsToMetres`). Implemented as a **configurable tweak** in HERCULAN Engine.
- Samson: When firing lasers from the two lowest hardpoints, the beams emerge from a little above the barrels. Not sure if this happens with all lasers or if it's hardpoint specific. Only visible in third-person view.
- A Razor nacelle strike draws its impact effect at the **left** nacelle whichever nacelle was struck. Reproduced as-is. See [`docs/simulation/razor-flight.md`](docs/simulation/razor-flight.md#contact-probes).
- The MFD TARGET screen (F5) can never read `SHIELDS DN` for a HERC target, because that status is latched only on the player's own Herc for the STATUS (F1) screen. Reproduced as-is. See [`docs/formats/mfd.md`](docs/formats/mfd.md#viewport-and-condition-per-class).
- The repair screen prints nonsense for a badly damaged component. Its Condition readout has six damage levels but only four words to name them, so a component between 1% and 29% reads `% Complete` and a destroyed one reads `Unassigned` — the next two unrelated entries in the text table. Confirmed in the disassembly. See [`docs/shell/screen-layout.md`](docs/shell/screen-layout.md#the-condition-readout).
- A second hit on the cockpit stops the damage shake instead of restarting it. Taking a hit shakes the view for about a second; a second hit inside that window clears the shake and extends the timer, but the check that would set it going again only passes when no shake is running — so the view goes still for the rest of the window while the palette carries on flashing. Reproduced as-is. See "The damage shake" in [`docs/formats/cockpit-canopy-palette.md`](docs/formats/cockpit-canopy-palette.md#the-damage-shake).
- The repair screen's damage diagram draws the torsos and the legs on opposite sides: Left Torso is on the viewer's left while Left Leg is on the viewer's right, and vice-versa. Reproduced as-is. See [`docs/shell/screen-layout.md`](docs/shell/screen-layout.md#the-damage-diagram).
- A shell tab picked with the **right** mouse button opens its screen but is left drawn unlit, and right-clicking the tab already open unlights it. The button fires on the release and then redraws the tab as released, after the tab has already marked itself as the open one. Read from the disassembly, not yet checked in retail. Reproduced as-is. See [`docs/shell/screen-layout.md`](docs/shell/screen-layout.md#the-widget-that-takes-a-click-decides-what-it-does).
- The mission screen's summary text miscounts its pages: a text that exactly fills its pages gets an extra empty page the down arrow scrolls to, and a text one line short of a full page cannot be paged at all (harmless, since it fits on the one page). Read from the disassembly, not yet checked in retail. Reproduced as-is. See [`docs/shell/screen-layout.md`](docs/shell/screen-layout.md#the-summary-text-box).
- After scrapping a weapon in the armory, its row is drawn as though it were no longer selected, all but its count, yet it still is: with weapons built by hand the next click on it queues a unit instead of selecting it. See [`docs/shell/screen-layout.md`](docs/shell/screen-layout.md#the-scrap-dialog).
- VSHELL's Preferences screen offers three repair modes, but the repair screen only has a line to print for the first two, so choosing "Manually Repair All Hercs" leaves the readout showing whatever it last held — `Manual Repair` unless the mode was Auto earlier in the session. Reproduced as-is. See [`docs/shell/screen-layout.md`](docs/shell/screen-layout.md#repairing-and-cancelling).

### Functional
- Player Herc acceleration/deceleration and turning are framerate-dependent (**fixed** in HERCULAN Engine)
- The "center legs" function moves the turret awkwardly and does not center the legs perfectly.
- Scrapping a Herc that is still under construction pays either nothing or its full price, never anything between: the yield is computed as `((100 - percentComplete) / 100) * price`, and that integer division collapses to zero for every progress figure from 1 to 99. Confirmed in the disassembly. See [`docs/shell/armory.md`](docs/shell/armory.md#scrapping).
- A squad pilot's skill rises for scoring nothing. Skill steps up when career Herc + Flyer kills hit a multiple of the pilot's divisor, and zero is a multiple — so a pilot who has never killed a machine is promoted after every mission survived until they reach ELITE. Confirmed in the disassembly: only the division remainder is tested, and nothing checks whether the kill total is zero. See [`docs/shell/campaign-loop.md`](docs/shell/campaign-loop.md#pilot-progression).
- Some buildings' collision volumes are shorter than the visible mesh, so shots pass through the top of the building.
- Turning with the keyboard turns at half of the speed of turning with the joystick.
- The turret motion stutters when aiming with a joystick. The drawn turret pose is quantized to about 0.45°, noticeable only with small analog inputs. **Fixed** in HERCULAN Engine by default; the residual step is about five times finer. See [`docs/simulation/torso-aim.md`](docs/simulation/torso-aim.md#angle-to-pose).
- A gun mount that has taken damage fires **faster**, not slower: past half damage, each further step shortens its refire delay, so a badly damaged autocannon refires up to twice as fast. Verified with disassembly. Reproduced as-is. See [`docs/simulation/weapon-mounts.md`](docs/simulation/weapon-mounts.md#losing-a-mount).
- The effect-light allocator has no full-table guard: with all twenty slots busy, the claim overruns into the caller's own position vector and the manager's embedded light object. **Not reproduced** in HERCULAN Engine. See [`docs/formats/effect-lights.md`](docs/formats/effect-lights.md#the-allocator-overruns-when-all-twenty-slots-are-busy).
- The impact point of a machine-versus-machine collision mixes two coordinate frames. On level ground near sea level the two nearly agree; on a hill the blast goes off well below the machines, and its falloff reaches their legs rather than their torsos. Reproduced as-is. See [`docs/simulation/damage-system.md`](docs/simulation/damage-system.md#a-collision--mech_collisiontest-00418f74).
- Starting a sound retunes any copy of it that is already playing. Volume and stereo position belong to the catalog entry rather than to the individual playback, and get applied to whichever copy is sounding at the moment the next one starts — so a nearby footstep jumps to the volume and position of a distant one that follows it. Reproduced as-is. See [`docs/formats/audio.md`](docs/formats/audio.md#a-repeated-play-layers-it-does-not-restart).
- The one looping sound shared by every fire in the mission is placed on whichever fire is nearest the camera, but the distance behind that choice is computed in 32-bit arithmetic that overflows past about 278 m, so a building burning beside the player can fall silent because something is burning a quarter-mile off. **Not reproduced** in HERCULAN Engine. See [`docs/simulation/destruction-effects.md`](docs/simulation/destruction-effects.md#where-the-shared-sound-is-heard).
- VIEW DEMO plays its recording as fast as the computer can draw it, so a demo several minutes long is over in about a second on a modern PC. **Not reproduced** in HERCULAN Engine, which plays a tape at the speed it was recorded. See [`docs/formats/tap-input-tape.md`](docs/formats/tap-input-tape.md#timing).
- In VSHELL, the "Saved Games" panel isn't centered vertically.
- Opening the WEAPONS tab without a usable Herc selected picks the first finished Herc using the rules of the tab you just left instead of the WEAPONS tab's own. Read from the disassembly, not yet checked in retail. **Not reproduced** in HERCULAN Engine, which applies the WEAPONS rule. See [`docs/shell/screen-layout.md`](docs/shell/screen-layout.md#entering-the-weapons-screen).
- On the WEAPONS screen, if you have select a hardpoint currently holding a missile rack, then click on an autocannon type you don't own, the missile launcher will be unequipped. Reproduced as-is. See [`docs/shell/screen-layout.md`](docs/shell/screen-layout.md#fitting-a-weapon).
- On the WEAPONS screen, after changing Herc or re-entering the tab, weapons the previously selected hardpoint could not take can stay greyed out until another row is clicked. Read from the disassembly, not yet checked in retail. Reproduced as-is. See [`docs/shell/screen-layout.md`](docs/shell/screen-layout.md#fitting-a-weapon).
- Mission music plays once and then stops instead of looping. The game waits for Windows to say the CD track has finished, and on Windows 11 the CD driver never says so. **Not reproduced** in HERCULAN Engine, which plays the disc's audio itself. See [`docs/formats/audio.md`](docs/formats/audio.md#cd-audio).

### AI
- When an AI machine picks which part of its target to shoot at, it looks at the damage on **its own** parts instead of the target's — so it works at whichever of its own components is worst hurt, limited to parts the target still has. Reproduced as-is. See [`docs/simulation/ai-targeting.md`](docs/simulation/ai-targeting.md#which-component-the-shot-is-aimed-at--mech_aiselectaimcomponent-0041ce08).
- Two AI machines compare their combat ratings through a random jitter that was meant to be `rand % 1000` but is written `rand & 1000`, so the jitter lands on only a few of the numbers in that range. Reproduced as-is. See [`docs/simulation/ai-targeting.md`](docs/simulation/ai-targeting.md#relative-combat-rating).
- A mission group only ever walks the route attached to its **first** order. Later orders carry routes of their own and several shipped missions set them, but the group's route is loaded once when it is built and never re-pointed, so a group that moves on to its second travel order is already out of waypoints. Reproduced as-is. See [`docs/simulation/ai-goals.md`](docs/simulation/ai-goals.md#the-route-cursor-is-loaded-once).
- A live group of HERCs with no orders at all would crash the game on its first AI frame: the state-selection function falls through with a null behaviour descriptor and dereferences it. No shipped mission has one — only structure groups go orderless, and structures have no AI. HERCULAN Engine leaves such a machine in the state it already held. See [`docs/simulation/ai-goals.md`](docs/simulation/ai-goals.md#a-group-with-no-order-at-all).
- For **flyer** groups, the `ram`, `guard` and `follow` orders are unimplemented: the state-selection function has no case for any of the three and leaves the aircraft's next behaviour undefined. What that does in retail is unknown, and whether any retail mission gives a flyer group one of them has not been checked. HERCULAN Engine ignores these orders. See [`docs/simulation/ai-flyers.md`](docs/simulation/ai-flyers.md#orders--flyer_aiselectbehaviour-00422d00).
- A group under a `travelling` order can skip waypoints. Every other movement state has the group leader alone walk the route while the rest hold formation, but `travelling` has every member walk it, and all of them step the one shared cursor — so a tightly-packed group crossing closely-spaced waypoints advances past several of them in a tick. Reproduced as-is. See [`docs/simulation/ai-navigation.md`](docs/simulation/ai-navigation.md#travelling-9-and-bulldog-travel-11--mech_behaviourtravelthink-0041d9cc).
- A `follow` order never finishes. Its completion test asks whether the group's route has run out, but nothing in the `following` behaviour ever advances the route cursor — so unless the group's route was empty to begin with, the only thing that can move the group off that order is the order's own mission action firing. Reproduced as-is. See [`docs/simulation/ai-navigation.md`](docs/simulation/ai-navigation.md#following-10--mech_behaviourfollowthink-0041daac).
- An AI Herc slows for nothing it steers around. Its obstacle avoidance can cut the throttle as well as the steering, but the distance that gates the cut is zero for terrain and for other machines, so the only obstruction that ever makes a machine back off is the player's own line of fire. Reproduced as-is. See [`docs/simulation/ai-navigation.md`](docs/simulation/ai-navigation.md#resolving-it).
- An AI machine picks its weapon against the target's **front** shield however the target is facing. It works out whether it is shooting the front or the back and then hands that yes/no answer to a routine expecting a compass bearing, and both answers read as "the front" there. Reproduced as-is. See [`docs/simulation/ai-weapons.md`](docs/simulation/ai-weapons.md#choosing-a-weapon--ai_chooseweapon-0041f358).
- A Cybrid's aim is thrown off in one direction only. The difficulty setting gives its shots a random spread, but the random draw is never negative. Reproduced as-is. See [`docs/simulation/ai-weapons.md`](docs/simulation/ai-weapons.md#the-fire-decision--ai_fireatpoint-0041f5a0).
- A Cybrid engaged in the "ramming" action will detonate when it hits *any* obstacle, not just its target. Reproduced as-is. See [`docs/simulation/ai-combat-states.md`](docs/simulation/ai-combat-states.md#the-charge--mech_behaviourramtick-0041e488).
- A Cybrid engaged in the "ramming" action blows itself up immediately if another Herc has ever walked into it. The "something ran into me" flag a collision leaves on a Herc is never cleared afterwards, and the ramming attack detonates on it. Reproduced as-is. See [`docs/simulation/ai-combat-states.md`](docs/simulation/ai-combat-states.md#the-charge--mech_behaviourramtick-0041e488).

## HERCULAN Engine

_Note to Claude: This section is for listing outstanding issues with features which have been implemented but behave differently than retail or otherwise incorrectly. Features that haven't been tackled yet go in [`ROADMAP.md`](ROADMAP.md). Bugs in retail belong in the previous section. Detailed technical descriptions belong in documentation, not here. Give a short plain-English summary._

- Terrain detail-texture scatter may still differ from retail: which cells draw the theater bank's alternate frame is a random roll whose alignment with DBSIM's own sequence isn't confirmed. See "Detail-texture scatter RNG" in [`docs/formats/terrain-texturing.md`](docs/formats/terrain-texturing.md#detail-texture-scatter-rng).
- Distance fog on terrain is smooth where retail's steps cell by cell. The amount of fog and the ground it lands on match; the flat step across each cell is missing. See "Engine port" in [`docs/formats/distance-fog-and-sky.md`](docs/formats/distance-fog-and-sky.md).
- `TSGouraudPoly` faces fade by an RGB blend toward the fog colour rather than by a ramp depth slice. Every other surface fogs through the ramp as retail does. Same section as above.
- Gouraud-shaded structures band differently from retail on some geometry, e.g. the type-15 octagonal tower: retail's wide dark bands are not reproducible under the engine's current shading mechanism, and the cause is unresolved. See "Type-15 band widths" in [`docs/formats/dts-texture-binding.md`](docs/formats/dts-texture-binding.md#type-15-band-widths). Reference captures: `Reference/Gouraud_shading_comparison_2.png`, `Reference/Scramble_Training_Base_4.png`.
- No back-face culling: retail's format has an explicit back-face skip flag that most of the fleet relies on. See "Front/back visibility test" in [`docs/formats/dts-texture-binding.md`](docs/formats/dts-texture-binding.md#implementation-status).
- A machine's fitted weapon models are drawn on the player's own HERC in the cockpit view, where its hull is not. Retail submits every machine in `GlobalMechList` with no local-player test at all (`maybe_Scene_SubmitFrameObjects`, `0042841c`); leaving the hull out is this engine's own device for keeping the torso from wrapping the camera, and the guns hang outside it.
- When projectiles hit buildings, many hit effects seem to clip inside the building - I don't observe this in retail. **Hit geometry ruled out**, and **building LOD ruled out** (the engine draws maximum detail, which is what retail's screenshots were taken at). Most likely a draw order issue.
- Due to nearest-neighbor scaling, text often looks bad when window height isn't an integer multiple of 240.
- In the Scramble practice mission while piloting an Apocalypse, a Particle Beam Weapon is equipped to slot 8. In HERCULAN, when this PBW is fired the beam visibly clips off near the corner of the screen. This may be a camera near-clip plane issue.
- With a damaged sensor array, the MFD and the weapon rows keep dropping out during a side glance, because the engine keeps the forward console on screen beside the side window; in retail the glance takes them off screen, which pauses their dropouts. See [`docs/formats/cockpit-hud-widgets.md`](docs/formats/cockpit-hud-widgets.md#when-each-display-ticks).
- The message port draws whenever it has a line, where retail gates the display half on two further fields that aren't decoded. See "The port" in [`docs/formats/cockpit-messages.md`](docs/formats/cockpit-messages.md#the-port).
- The cockpit shows the two side windows beside the forward view at all times, cropped to the window, where retail shows one view at a time. A glance (`[F9]`/`[F10]`, the hat, the side screen edges) therefore slides the three panels only until the side panel's outer edge meets the window's edge; retail slides one whole panel. In a 4:3 window the two are the same, and in a wider one the glance is shorter and leaves part of the forward view on screen. The side screen-edge strips sit on the window's edges rather than on the forward view's, which here are mid-screen. See `Render.CockpitGlance` and `CockpitScreenLayout.SideViewEdgeAt`.
- With `--developer`, `Alt+Left`/`Right` move the HERC sideways without also turning it, and `Alt+Up`/`Down` and `Ctrl+Left`/`Right` likewise leave the steering and throttle alone. In retail the arrow keeps its ordinary job alongside the developer one. Deliberate: without the turn, the sideways move can be seen. See [`docs/key-bindings.md`](docs/key-bindings.md#herculan-engine).
- The `[V]` external view is placeholder rather than retail's. See [`ROADMAP.md`](ROADMAP.md).
- Steering a Razor from the keyboard uses hardcoded placeholder keys. See [`docs/simulation/razor-flight.md`](docs/simulation/razor-flight.md#the-keyboard).
- Every mission plays CD track 2. In retail the launcher moves to the next of the five mission tracks each time a mission starts. See [`docs/command-line.md`](docs/command-line.md#the-loop).
- Mid-session audio system recovery is not implemented. If the endpoint drops during gameplay, the engine stays silent for good. See [`docs/formats/audio.md`](docs/formats/audio.md#open).
- On a CD drive that refuses digital audio reads, the engine falls back to having the drive play the music, as retail does. That fallback checks for the end of the track five times a second, so the loop can have a gap of up to a fifth of a second. See "CD music" in [`docs/formats/audio.md`](docs/formats/audio.md#cd-music).
- The shell's tab strip stays on screen while the MAIN MENU tab is up. In retail the main menu hides it, as the save screen does; the engine keeps it because nothing is ported behind that tab yet, so hiding it would leave nothing to click. See [`docs/shell/screen-layout.md`](docs/shell/screen-layout.md#engine-coverage).
- The shell's Herc scrap dialog blocks every click but its CANCEL and ACCEPT. Whether retail's does is not yet established. See [`docs/shell/screen-layout.md`](docs/shell/screen-layout.md#the-scrap-dialog).
- With no hangar bay selected, the build screen greys SCRAP and BUILD. Retail reads a squad-member pointer where the bay's machine would be, with unexplored results. Same doc, "Scrapping and building are gated on the bay".
- With no hangar bay selected, the WEAPONS screen's hardpoint steppers do nothing. Retail steps through the same squad-member pointer, with unexplored results. See [`docs/shell/screen-layout.md`](docs/shell/screen-layout.md#fitting-a-weapon).
- Claude made many mistakes in the AI code by confusing different status conditions for mechs. For example, "disarmed" has a different meaning than "immobilized" or "destroyed", so even if they are used equivalently by some functions, treating them as synonymous throughout the code causes bugs. Several issues have been fixed, but more may exist, so we need a full-pass review against retail.
